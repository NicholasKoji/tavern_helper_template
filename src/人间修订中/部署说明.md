# 人间修订中在线界面部署

在线发布只上传三个自包含资源：

- `human-revision/world-config/index.html`
- `human-revision/status/index.html`
- `human-revision/schema/index.js`

`scripts/human-revision-release.mjs` 会从 `dist/人间修订中/` 复制资源到隔离 staging 目录，并生成 Cloudflare Pages
`_headers`。请求头契约为：

- `Cache-Control: no-cache, must-revalidate`
- `Access-Control-Allow-Origin: *`
- HTML 使用 `text/html`，变量结构使用 `application/javascript`
- 静态服务必须返回 `ETag`，并以 `If-None-Match` 返回 `304`

本地构建与等价验证：

```powershell
pnpm build
pnpm run human-revision:verify
```

Cloudflare Pages 需要在本机或 GitHub Actions 中提供以下配置：

- Secret `CLOUDFLARE_API_TOKEN`
- Secret `CLOUDFLARE_ACCOUNT_ID`
- Repository variable `HUMAN_REVISION_PAGES_PROJECT`
- Repository variable `HUMAN_REVISION_PAGES_BASE_URL`

部署命令为 `pnpm run human-revision:deploy`。该命令使用 `HUMAN_REVISION_PAGES_ONLY=true`
构建前端，跳过 schema 导出和 tavern_sync 打包，然后执行隔离 staging、Pages 原子部署和线上三资源响应头/ETag/304 验证。

角色卡加载器优先读取宿主页面的 `globalThis.__HUMAN_REVISION_PAGES_BASE_URL__`，再回退到 `codex/zaohua-nongren`
稳定分支的 raw/jsDelivr 地址。绑定真实 Pages 域名后，将该全局配置注入酒馆宿主；分支地址仅作为应急回退，不携带提交 SHA 或 Git
tag。
